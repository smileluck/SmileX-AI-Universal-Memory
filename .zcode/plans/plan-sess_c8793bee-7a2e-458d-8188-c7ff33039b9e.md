# 新增 LoCoMo Benchmark（复用 LongMemEval 工具链）

## 目标
在 `benchmarks/locomo/` 新建与 `longmemeval/` 平级的评测管线，跑通 LoCoMo 数据集的 ingest → recall → answer → 打分全流程，并输出按题型分类的报告。

## 目录结构
```
benchmarks/locomo/
├── download_dataset.py   # HF 下载 LoCoMo（如 sownmoon/locomo 或官方 JSON，10 个长对话样本）
├── ingest.py             # 解析 LoCoMo 单超长对话（~300 turns，~9K tokens），按 MAX_CHUNK_CHARS 切块写入
├── answer.py             # 复用 recall + LLM 生成骨架
├── judge.py              # MCQ 题正则/精确匹配判分；open-domain 题用 LLM-as-judge
├── run_benchmark.py      # checkpoint/resume + 报告框架（同 longmemeval 模式）
└── llm_client.py         # 从 longmemeval 复制（保持环境变量约定 SMILEX_BENCH_*）
```

## 关键设计点
1. **数据格式适配**：LoCoMo 每个样本是一个 session 长对话（不是 haystack_sessions 列表），`ingest.py` 需按 `speaker: utterance` 渲染后切块写入；对话内时间戳作为 `[date: ...]` 前缀（服务 temporal 题）。
2. **题型与判分**：LoCoMo 五类题 — single-hop / multi-hop / temporal / open-domain / adversarial：
   - MCQ（adversarial 等）：答案为选项字母，用精确匹配，省 judge 调用
   - 开放式（single/multi-hop 等）：LLM-as-judge（复用现有 judge prompt），同时报 JUDGE 正确率
   - 报告按 `category` 分组输出准确率，与论文口径对齐
3. **复用组件**：`MemoryMiddleware(db_path, embedder, promotion_threshold=0)` 写入方式、`mw.recall` + 4K token budget 作答、checkpoint 跳题、异常按 0 分不中断。BM25+FTS5 双通道经 ContextBuilder 自动生效，无需额外接线。
4. **不抽取公共库**：longmemeval 目前用 `sys.path.insert` 裸 import，为保持一致，locomo 先平级复制小文件（llm_client/judge），避免大重构。

## 运行方式（与现有约定一致）
```
uv run python benchmarks/locomo/download_dataset.py
uv run python benchmarks/locomo/run_benchmark.py --limit 10 [--resume] [--dump-context]
```

## 验证
- 先 `--limit 1` 冒烟（可用 `_smoke_stub.py` 思路验证管线），确认数据解析与判分正确，再跑全量 10 个对话的题目。
