# 新增 benchmarks/mem0_compat/ — mem0 口径兼容 runner

## 目标
新建一套与 mem0 官方 [memory-benchmarks](https://github.com/mem0ai/memory-benchmarks) 评测协议对齐的 runner，使分数可直接与 mem0 公布的 LoCoMo 92.5 / LongMemEval 94.4 对比。现有 benchmark 保留（自家严口径），两套并存、报告里注明口径。

## 目录结构
```
benchmarks/mem0_compat/
├── mem0_prompts.py   # mem0 官方 prompt 逐字移植(英文原文)
│                     #   locomo: 7步作答模板 + 宽松judge(CORRECT/WRONG JSON)
│                     #   longmemeval: 14条规则作答 + anti-"no" judge(yes/no)
├── common.py         # cutoffs 切片逻辑 / 按题型分层采样(seed) / 指标计算 /
│                     #   时间序记忆格式化 / db 读全文助手
├── locomo.py         # LoCoMo mem0 口径 runner
├── longmemeval.py    # LongMemEval mem0 口径 runner
└── results/          # (gitignore 同现有约定)
```
复用：`longmemeval/llm_client.py`（importlib 加载，保持 GLM 环境变量约定）、两处切块函数、`retrieval_baseline` 已验证的「recall() → sources 排名」读取方式。

## 协议对齐要点（与 mem0 run.py 逐项对齐）

### LoCoMo（locomo.py）
- **题目范围**：categories 1-4 全量（~1540 题），**排除 adversarial(5)**——与 mem0 分母一致
- **cat-3 temporal 的 gold**：取分号前第一段（mem0 `preprocess_answer` 同款）
- **检索**：`recall(top_k=200, token_budget=∞)` 一次取全，**cutoffs 10/20/50/200** 各评一次（答案+判卷独立跑）
- **记忆呈现**：按时间序（ingest 顺序即时间序）、不显示 score/rank；answerer 记忆上限 200
- **作答 prompt**：mem0 7 步模板逐字移植——含 reference_date（取对话最后 session 日期）、"NEVER say not specified"、"events occurred in 2022-2024" 等
- **判卷 prompt**：mem0 宽松 judge 逐字移植——PARTIAL CREDIT（对 1/2 即对）、PARAPHRASES COUNT、日期 ±14 天容忍、EXTRA DETAIL FINE，输出 JSON `{reasoning, label: CORRECT|WRONG}`
- 每对话独立 db + checkpoint（复用 locomo benchmark 的 `(conv_idx, q_idx)` 模式，一条记录含全部 cutoffs）

### LongMemEval（longmemeval.py）
- **采样**：默认 `--per-type 5 --seed 42` 分层采样 30 题（mem0 默认口径）；`--all-questions` 跑 500
- **数据源**：`--source original|cleaned`，默认 original（保持连续），cleaned 切到 mem0 用的 `xiaowu0162/longmemeval-cleaned` 的 `longmemeval_s_cleaned.json`
- **每题独立 db**（现有 longmemeval 模式即 mem0 的 per-question user_id 语义）
- **作答 prompt**：question_date 作为 today、`<mem_thinking>` 隐藏推理、14 条规则（含 most-recent-wins、拒答话术 "The information provided is not enough"）
- **判卷 prompt**：anti-"no" 偏差校正、off-by-one 容忍、拒答即匹配 abstention gold；`judge_yes_no` 取最后一个 yes/no
- 同样 cutoffs 10/20/50/200

### 指标（common.py）
- 每个 cutoff 独立计算 Overall + 分题型，**headline = 最大 cutoff(200)**（mem0 `compute_overall_metrics` 同款）
- 结果 JSON+MD，标注口径 "mem0-compatible protocol, answerer/judge=GLM(与 mem0 gpt-5 不同，需注明)"

## 技术要点
1. **top-200 全文读取**：`MemoryRef.snippet` 截断 120 字符不够作答，`common.py` 提供按 sources[].id 从 fragments 表读全文的助手（直接 SQL，与 storage schema v13 一致）
2. **GLM 适配**：judge 需解析 JSON/yes-no，GLM thinking 模式可能耗尽 max_tokens——judge 关思考（llm_client 现成 `disable_thinking`），answerer 开思考给足 4096
3. **模型差异注明**：mem0 用 gpt-5 answerer+judge，我们默认 GLM——报告头部显式打印，README 对比表加脚注

## 验证
- LoCoMo：`--conversations 0 --max-qa 2` 冒烟（4 cutoffs × 2 题全链路，需用户提供 OPENAI_API_KEY/GLM key）
- LongMemEval：`--per-type 1` 冒烟 6 题
- 断点续跑验证：中断后 `--resume` 跳过已完成题
