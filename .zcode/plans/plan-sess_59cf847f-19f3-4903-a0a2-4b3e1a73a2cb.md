# 初始化项目 = 扫描并生成初始记忆（README + git 历史 + markdown 文档）

## 现状与思路
`BulkImporter` 已具备 git/markdown/text → L1 记忆 + 实体/三元组种子的能力（幂等、git 带断点续传），但只暴露在 Python SDK；MCP `memory_init_project` 只收手动贴的 README 文本；CLI `init` 只写 MCP 配置。本次把这条链路接到 MCP 工具与 CLI 两个入口，共用同一编排方法，并补齐幂等根基。

## 改动清单（7 项）

### 1. scope 按项目名复用 — `src/smilex/memory/scheduler/bootstrap/project_bootstrap.py`
`initialize()` 目前每次都 `generate_id()` 新建 `project:{ulid}`，重复初始化会产生重复 scope，扫描无法幂等重跑。改为：入口先查 `SELECT scope FROM entities WHERE entity_id = 'project:{normalize_name(name)}' AND valid_to IS NULL LIMIT 1`，命中则复用该 scope，未命中才新建。entity_id 全局稳定（如 `project:smilex-ai-universal-memory`），entities 表有 (scope, entity_id) 索引，此查询走 entity_id 条件、冷启动量级无性能问题。

### 2. markdown 扫描忽略规则 — `src/smilex/memory/scheduler/bootstrap/bulk_importer.py`
`_import_markdown` 目前裸 `rglob("*.md")`，会吃进 node_modules/.venv 等。改为：
- 过滤相对路径中任一段命中 `EXCLUDED_DIRS`（`.git/.smilex/node_modules/.venv/venv/.build/dist/build/site-packages/__pycache__/.idea/.vscode`）或以 `.` 开头的隐藏目录的文件
- `ImportSource` 新增 `max_files: int = 500` 上限，超限截断并在 `ImportResult.errors` 记提示

### 3. 共享编排方法 — `src/smilex/middlewares/memory.py`（M.2 区新增）
```python
async def bootstrap_project(name, *, project_path=None, description="",
    tech_stack=None, readme_content=None, scan_git=True, scan_markdown=True,
    max_commits=None) -> dict
```
- `readme_content` 缺省且 `project_path` 给定时：自动读项目根 `README*.md` 第一个匹配
- 依次执行：`initialize_project`（改动 1 后幂等）→ `.git` 存在且 scan_git 时 `import_source(GIT)` → scan_markdown 时 `import_source(MARKDOWN, path=project_path)`
- 单源失败（如无 .git、git 不可用）记为 skipped/错误信息，不中断其他源
- 返回 `{"init": ..., "imports": {"git": ..., "markdown": ...}, "project_path": ...}`

### 4. MCP 工具扩展 — `src/smilex/server/mcp_server.py`
`memory_init_project` 新增参数 `project_path/scan_git/scan_markdown/max_commits`，内部改调 `bootstrap_project`；工具 description 与模块顶部工具约定注释同步更新。stdio 模式下 `project_path` 缺省时从 `config.resolved_db_path()` 自动推断项目根（匹配 `<root>/.smilex/memory.db` 模式）；HTTP 全局模式不推断，需显式传参。

### 5. CLI `init --scan` — `src/smilex/cli.py`
- `init` 子命令加 `--scan` 开关：注入配置后执行同一套扫描导入
- db 选择：`--stdio` → 项目内 `<dir>/.smilex/memory.db`；HTTP 模式 → 全局库（打印「直接写入全局库，建议服务空闲时执行」的提示）
- 把 `MemoryService.get()` 里 embedder/reranker/extractor 的组装逻辑抽成公共 helper（如 `build_middleware(config)`），CLI 与 MemoryService 共用，保证 embedder 配置一致
- 项目名缺省取 `project_dir.name`；打印各源导入统计
- `_GUIDE_TEXT` 更新：冷启动一行改为 `memory_init_project(name, project_path=...)`（自动读 README + 扫 git/markdown）

### 6. 测试（延续现有测试文件风格）
- `test_bootstrap.py`：同名项目二次 initialize → scope 复用、实体/三元组计数不翻倍
- `test_importer.py`：忽略规则（node_modules/隐藏目录下 md 不导入）、max_files 截断
- `test_mcp_tools.py`（或新文件）：`bootstrap_project` 编排（tmp 项目含 README + docs/*.md + git init/commit；无 .git 时 git 源 skipped）；`memory_init_project(project_path=...)` 工具层往返
- CLI `--scan`：stdio 模式指向 tmp 项目，断言 `.smilex/memory.db` 产生 temporal_fragments；重复执行计数不变（幂等）；不触碰真实 `~/.smilex`
