# Server 面板优化方案(视觉+功能全面升级)

保持不变的约束:纯 vanilla JS、零依赖、无构建、离线可用(不引 CDN);面板只读原则;`/api` → 静态面板 → MCP 挂载的路由布局不变。

## 一、视觉方向

概念是「记忆地层学」:这套系统的核心信息结构就是 L0-L3 四层记忆,把"层"作为贯穿整个面板的视觉编码,而不是通用后台模板。

- **签名元素**:概览页的「分层叠条」——一根纯 CSS 堆叠条,L0/L1/L2/L3 各占一段(宽度=占比),带图例和计数,把 `fragments_by_layer` 这份后端已返回但一直没用的数据变成面板的视觉锚点。
- **色彩**:墨蓝黑底 + 四个层色(L0 琥珀 / L1 青 / L2 紫 / L3 绿,具体色值实现时定)+ 中性文本;全部走 CSS custom properties,kind/layer 徽标、进度条、来源分数条复用同一套层色。
- **字体**:界面文本用 system-ui;数据(ID、时间戳、分数、SQL 时间)统一 ui-monospace 栈 + tabular-nums,强化"本地仪表"质感。
- **质量底线**:键盘焦点可见、prefers-reduced-motion、窄屏响应(卡片换行、表格横向滚动)。

## 二、后端改动(`src/smilex/server/api.py`,全部只读)

1. **`/api/stats` 扩展**:新增 `l0_snapshots`(memory_l0_snapshot 计数)、`causal_chains` 计数、`db_size_bytes`。
2. **新增 `GET /api/health`**:started_at/uptime(路由创建时记时间戳)+ 配置摘要(embedder/reranker/fact_extractor/调度器开关/token_budget/db 路径),给面板顶部状态区轮询用。
3. **`/api/memories` 的 `q` 改走 FTS5**:fragments 从 LIKE 改为 `fts_fragments MATCH`(013 号 schema 的 trigram 表,CJK 子串通吃,触发器已自动同步),`q` 存在时按 bm25 相关度排序;MATCH 串用双引号包裹转义,防用户输入语法错误;entities/triples 维持 LIKE。无 FTS 报错时回退 LIKE(兼容异常库)。
4. **修一个现存 bug**:召回来源 `MemoryRef.to_dict()` 键是 `id`,面板读 `s.memory_id` 导致该列一直空白——前端改读 `s.id`,不动共享 DTO。

## 三、前端改动(重写 `panel/` 三个文件)

**概览 tab**:6 张统计卡(实体/三元组/时序片段/向量链接/L0 会话/因果链,千分位数字)+ 分层叠条 + scope 分布 chips(点击跳浏览 tab 并预填 scope)+ 任务表(进度条+相对时间)+ 顶部健康徽标区;15s 自动刷新(可开关,`document.hidden` 时暂停)。

**浏览 tab**:新增 kind 过滤(fragment/entity/triple)和 limit 选择(50/100/200/500);kind/layer 彩色徽标;**行点击打开右侧详情抽屉**(调已有但从未被用的 `/api/memory/{id}`,全字段键值展示,Esc 关闭)。

**召回 tab**:暴露 `session_id`、`token_budget` 参数;来源表补全 scope/snippet/score 条形;上下文加 copy 按钮;命中层显示为彩色徽标。

**全局**:统一 fetch 封装(错误/空态文案)、相对时间助手、激活 tab 记忆(localStorage)。
